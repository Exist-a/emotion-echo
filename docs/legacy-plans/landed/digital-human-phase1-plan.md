# 数字人功能技术方案

## 一、需求分析

### 1.1 核心需求

| 需求点 | 描述 | 优先级 |
|-------|------|--------|
| 3D 数字人渲染 | 在页面上渲染一个 3D 数字人形象 | 高 |
| 语音合成（TTS） | AI 回复内容通过语音播放 | 高 |
| 口型动画 | 数字人嘴巴随语音同步动 | 中 |
| 情绪动作 | 根据对话情绪展示预设动作 | 中 |
| 可拖拽定位 | 用户可自由拖动数字人位置 | 中 |
| 显示开关 | 按钮控制是否显示数字人 | 中 |
| 语音开关 | 按钮控制是否播放语音 | 中 |

### 1.2 UI 设计需求

- **默认位置**：页面右上角
- **外观**：圆形包边，数字人在圆形内展示
- **交互**：支持鼠标拖拽移动

---

## 二、技术选型

### 2.1 3D 渲染

| 方案 | 描述 | 优缺点 |
|------|------|--------|
| **Three.js** | 轻量级 WebGL 3D 库 | 优点：轻量、成熟、社区活跃<br>缺点：需要手动处理动画 |
| **Babylon.js** | 功能丰富的 3D 引擎 | 优点：内置骨骼动画支持<br>缺点：体积较大 |

**选择**：Three.js（轻量且足够满足当前需求）

### 2.2 语音合成（TTS）

| 方案 | 描述 | 优缺点 |
|------|------|--------|
| **XTTS** | 开源本地 TTS 模型（基于Coqui） | 优点：开源免费、可本地部署、多语言支持、语音质量高<br>缺点：需要单独部署服务、依赖Python 3.11 |
| **Web Speech API** | 浏览器内置 TTS | 优点：无需额外部署<br>缺点：语音质量不一、平台差异大 |
| **Edge TTS** | Microsoft Edge 浏览器的 TTS | 优点：质量较好、免费<br>缺点：依赖 Edge 浏览器 |

**选择**：XTTS（本地部署，与现有模型架构一致，已在项目中集成）

### 2.3 动画方案

- **口型同步**：使用语音波形数据驱动口型形状
- **情绪动作**：预设几种情绪状态（开心、伤心、中性、思考）

## 三、架构设计

### 3.1 系统架构图

```
┌─────────────────────────────────────────────────────────────────┐
│                        前端应用                                  │
├─────────────────────────────────────────────────────────────────┤
│  ┌─────────────────┐    ┌─────────────────┐    ┌─────────────┐ │
│  │   DigitalHuman  │    │    TTSPlayer    │    │ MessageStore│ │
│  │     组件        │    │    语音播放器    │    │   消息状态   │ │
│  └────────┬────────┘    └────────┬────────┘    └──────┬──────┘ │
│           │                      │                     │        │
│           ▼                      ▼                     ▼        │
│  ┌─────────────────────────────────────────────────────────────┐│
│  │                    DigitalHumanStore (状态管理)              ││
│  └─────────────────────────────────────────────────────────────┘│
├─────────────────────────────────────────────────────────────────┤
│                        后端服务                                  │
├─────────────────────────────────────────────────────────────────┤
│  ┌─────────────────┐    ┌─────────────────┐                    │
│  │   AI Service    │    │   TTS Service   │                    │
│  │   对话服务      │    │   语音合成服务  │                    │
│  └─────────────────┘    └─────────────────┘                    │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 组件结构

```
DigitalHuman (组件)
├── ThreeJSRenderer (3D渲染器)
├── PositionController (位置控制)
├── ExpressionController (表情/动作控制)
└── DragHandler (拖拽处理器)
```

### 3.3 数据流

1. **消息发送**：用户发送消息 → MessageStore 更新 → DigitalHumanStore 监听
2. **AI 回复**：收到 AI 回复 → DigitalHumanStore 触发语音合成 → TTSPlayer 播放
3. **动画同步**：TTSPlayer 播放 → 实时计算口型参数 → 更新数字人模型

## 四、API 接口设计

### 4.1 TTS 服务接口

| 接口 | 方法 | 描述 |
|------|------|------|
| `/api/tts/synthesize` | POST | 文本转语音 |

**请求体**：
```json
{
  "text": "你好，有什么可以帮助你的？",
  "voice": "female",
  "speed": 1.0
}
```

**响应**：
```json
{
  "audio_base64": "base64编码的音频数据",
  "phonemes": [
    {"char": "你", "start": 0, "duration": 0.15},
    {"char": "好", "start": 0.15, "duration": 0.2}
  ]
}
```

## 五、核心功能实现

### 5.1 数字人组件

**文件路径**：`app/components/digital-human/DigitalHuman.vue`

**功能**：
- 渲染 3D 数字人模型
- 支持拖拽定位
- 显示/隐藏切换

### 5.2 语音播放器

**文件路径**：`app/composables/useTTSPlayer.ts`

**功能**：
- 调用 TTS 服务合成语音
- 播放音频
- 实时计算口型参数

### 5.3 状态管理

**文件路径**：`app/stores/digitalHuman.ts`

**状态字段**：
| 字段 | 类型 | 描述 |
|------|------|------|
| `visible` | boolean | 是否显示数字人 |
| `speaking` | boolean | 是否正在说话 |
| `position` | {x: number, y: number} | 当前位置 |
| `emotion` | string | 当前情绪状态 |
| `enabled` | boolean | 是否启用数字人功能 |

## 七、部署方案

### 7.1 项目服务端口

| 服务 | 端口 | 说明 |
|------|------|------|
| 前端 | 3000 | Nuxt.js 前端 |
| 后端 | 8080 | Go Gin 后端 |
| 情绪识别 | 8002 | SenseVoice 情绪识别服务 |
| XTTS 语音合成 | 8003 | XTTS 语音合成服务 |

### 7.2 服务启动命令

#### 1. 前端启动
```bash
cd Emotion-Echo-Web
npm install
npm run dev
```

#### 2. 后端启动
```bash
cd Emotion-Echo-Gin
go mod download
go run cmd/server/main.go
```

#### 3. 情绪识别服务（SenseVoice）
```bash
# 假设在 Emotion-Echo-LLM 目录下，根据实际部署位置调整
# 请参考项目中的相关部署文档
```

#### 4. XTTS 语音合成服务
```bash
# 进入 XTTS 目录
cd Emotion-Echo-LLM/XTTS

# 激活 Python 3.11 虚拟环境（假设虚拟环境名为 coqui-tts）
conda activate coqui-tts

# 启动服务（端口 8003）
# 根据实际部署方式执行启动命令
```

### 7.3 XTTS 环境配置注意事项

- **Python 版本**：必须使用 Python 3.11（3.12 不兼容）
- **PyTorch 版本**：建议使用 PyTorch 2.5.1（2.6.0 可能有问题）
- **依赖包**：需要安装 transformers==4.40.2、hangul_romanize、num2words、spacy、mutagen、pandas 等
- **模型位置**：`Emotion-Echo-LLM/XTTS/AI-ModelScope/XTTS-v2/`

### 7.4 前端集成

- **VRM 模型位置**：放在 `Emotion-Echo-Web/public/3d-models/` 目录下
- **默认模型路径**：`/3d-models/digital-human.vrm`
- **数字人组件**：`app/components/digital-human/DigitalHuman.vue`

## 八、安全考虑

1. **音频数据处理**：确保音频传输使用 HTTPS
2. **用户隐私**：不在服务端保存用户语音数据
3. **资源限制**：添加音频播放时长限制，防止滥用

## 十、风险评估

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| TTS 服务延迟 | 语音播放延迟 | 添加加载状态提示 |
| 3D 渲染性能 | 低配置设备卡顿 | 提供 2D 降级方案 |
| 口型同步精度 | 口型与语音不同步 | 使用 phonemes 数据驱动 |
| 模型加载失败 | 数字人无法显示 | 添加错误处理和默认头像 |
