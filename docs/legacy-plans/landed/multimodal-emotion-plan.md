### 2.2 多模态融合流程

```
用户发送消息
      │
      ▼
┌─────────────────────────────────────────────────────────────┐
│                      判断消息类型                             │
└─────────────────────────────────────────────────────────────┘
                              │
         ┌────────────────────┼────────────────────┐
         │                    │                    │
         ▼                    ▼                    ▼
┌─────────────────┐  ┌─────────────────┐  ┌─────────────────┐
│    纯文字消息    │  │    语音消息     │  │    混合消息     │
│                 │  │                 │  │ (文字+语音)     │
└────────┬────────┘  └────────┬────────┘  └────────┬────────┘
         │                    │                    │
         │              SenseVoice           SenseVoice
         │                    │                    │
         │                    ▼                    ▼
         │          ┌─────────────────┐  ┌─────────────────┐
         │          │ 获取语音情绪     │  │ 获取语音情绪     │
         │          │ + 文字内容       │  │ + 文字内容       │
         │          └─────────────────┘  └─────────────────┘
         │                    │                    │
         └────────────────────┴────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                    多模态情绪融合                             │
│                                                             │
│  ┌───────────────────────────────────────────────────────┐ │
│  │ 融合权重 (固定，暂不开放配置)                           │ │
│  │ - 面部情绪 Face:   0.5                                 │ │
│  │ - 语音情绪 Voice:  0.3                                 │ │
│  │ - 文字情绪 Text:   0.2                                 │ │
│  └───────────────────────────────────────────────────────┘ │
│                                                             │
│  ┌───────────────────────────────────────────────────────┐ │
│  │ 融合规则:                                              │ │
│  │ 1. 归一化各情绪置信度到 0-1                            │ │
│  │ 2. FinalScore[emotion] =                              │ │
│  │      Face(0.5) * faceScore[emotion] +                 │ │
│  │      Voice(0.3) * voiceScore[emotion] +                │ │
│  │      Text(0.2) * textScore[emotion]                   │ │
│  │ 3. 取 FinalScore 最高的作为最终情绪                     │ │
│  └───────────────────────────────────────────────────────┘ │
│                                                             │
│  ┌───────────────────────────────────────────────────────┐ │
│  │ 特殊情况处理:                                          │ │
│  │ - 面部不可用: Voice(0.6) * voice + Text(0.4) * text   │ │
│  │ - 语音不可用: Face(0.6) * face + Text(0.4) * text    │ │
│  │ - 文字不可用: Face(0.7) * face + Voice(0.3) * voice  │ │
│  │ - 全部不可用: neutral, confidence = 0.5               │ │
│  └───────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│              融入 AI 疏导上下文                              │
│                                                             │
│  - 最终情绪 → 带入 emotion workflow                         │
│  - 置信度 → 影响 system prompt 强度                         │
│  - 触发 Kimi API 生成回复                                   │
└─────────────────────────────────────────────────────────────┘
```

## 三、数据模型设计

### 3.1 前端 → 后端

#### 面部关键点请求

```typescript
// POST /api/face/emotion
interface FaceEmotionRequest {
  userId: number;
  sessionId: string;
  timestamp: number;        // 毫秒时间戳
  landmarks: Array<{
    x: number;               // 归一化坐标 0-1
    y: number;
    z: number;
  }>;                        // 468个点
}
```

#### 消息请求扩展（携带面部情绪上下文）

```typescript
// POST /api/chat/stream
interface StreamRequest {
  conversationId?: string;
  message: string;
  emotion?: string;          // 新增：面部情绪（如果有）
  voiceEmotion?: string;     // 现有：语音情绪
  model?: string;
  shouldGenerateTitle?: boolean;
}
```

### 3.2 后端 → 前端

#### 面部情绪响应

```typescript
interface FaceEmotionResponse {
  emotion: string;            // happy, sad, angry, anxious, neutral, unk
  confidence: number;         // 0-1
  processedAt: number;        // 处理时间戳
}
```

### 3.3 Redis 存储

```
Key模式: face:emotion:{userId}:{sessionId}

Value (JSON):
{
  "emotion": "happy",
  "confidence": 0.85,
  "timestamp": 1704067200000
}

TTL: 3秒
```

### 3.4 数据库扩展

#### 新增表：暂不需要

面部情绪分析结果**不持久化存储**，仅Redis临时存储供实时融合使用。

如需后续分析，可在消息表中增加字段：

```sql
ALTER TABLE messages ADD COLUMN face_emotion VARCHAR(20);
ALTER TABLE messages ADD COLUMN face_confidence DECIMAL(3,2);
```

## 四、API接口设计

### 4.1 面部情绪分析接口

```
POST /api/face/emotion
```

**请求头**：
```
Authorization: Bearer {token}
Content-Type: application/json
```

**请求体**：
```json
{
  "userId": 12345,
  "sessionId": "conv_abc123",
  "timestamp": 1704067200000,
  "landmarks": [
    {"x": 0.482, "y": 0.295, "z": -0.039},
    {"x": 0.485, "y": 0.283, "z": -0.038}
  ]
}
```

**响应**：
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "emotion": "happy",
    "confidence": 0.85,
    "processedAt": 1704067200100
  }
}
```

**错误码**：
| code | 说明 |
|------|------|
| 0 | 成功 |
| 40001 | 参数错误 |
| 40002 | 人脸未检测到 |
| 50001 | FER服务不可用 |
| 50002 | Redis存储失败 |

---

### 4.2 流式对话接口（扩展）

```
POST /api/chat/stream
```

**新增请求字段**：
```json
{
  "faceEmotion": "happy",
  "faceConfidence": 0.85
}
```

**说明**：前端在发送消息时，将最近一次面部情绪结果一并发送。后端进行多模态融合时作为参考输入。

## 六、部署与配置建议

### 6.1 FER 服务部署

与 SenseVoice 同目录部署，共享 Python 环境。

**目录结构**：
```
Emotion-Echo-LLM/
├── sensevoice-small/     # 现有：语音识别服务 (:8002)
├── fer/                  # 新增：FER 情绪识别服务 (:8003)
│   ├── server.py         # FastAPI 服务
│   ├── fer_model/        # FER 模型文件
│   ├── requirements.txt  # 依赖
│   └── ...
└── ...
```

**FER 服务 API**：

```python
# POST /analyze
@app.post("/analyze")
async def analyze_landmarks(request: LandmarksRequest):
    """
    输入: { landmarks: [[x,y,z], ...] }  # 468个点
    输出: { emotion: str, confidence: float }
    """
```

### 6.2 配置项

```yaml
# config.yaml
ai:
  face:
    enabled: true
    captureInterval: 2        # 抓拍间隔（秒）
    redisTTL: 3              # Redis过期时间（秒）
    weights:
      face: 0.5
      voice: 0.3
      text: 0.2
  fer:
    baseURL: "http://localhost:8003"
    timeout: 10              # 请求超时（秒）
```

### 6.3 资源需求

| 服务 | CPU | 内存 | 磁盘 |
|------|-----|------|------|
| SenseVoice | 2核+ | 4GB+ | 模型约2GB |
| FER | 2核 | 2GB | 模型约100MB |

**建议**：FER 和 SenseVoice 可部署在同一台机器上，共享资源。

## 七、后续优化方向

| 优先级 | 优化项 | 说明 |
|--------|--------|------|
| P0 | 可配置权重 | 后续通过配置或数据库控制三模态权重 |
| P1 | 异步存档 | 面部情绪异步写入消息表，用于数据分析 |
| P1 | 异常检测 | 面部与文字/语音情绪差异大时，提高抓拍频率 |
| P2 | 多脸支持 | 画面中有多人时，选择最大/最清晰的脸 |
| P2 | 质量评分 | 评估人脸图像质量，过低时跳过分析 |
