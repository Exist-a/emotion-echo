## 2. 清偿原则

沿用 2026-09-18 的单一判据（避免"看心情"）：

> **必要 = 现在不做的确会造成未被发现的危害；不必 = 只是账面整洁，当前无实际危害。**

本轮另加三条**反自欺**规则（针对已发生过的失真模式）：

| # | 规则 | 防的是 |
|---|------|-------|
| P1 | **不许用改措辞消掉 WARN/FAIL**。除非在报告中**显式声明**"该证据形态缺口已记录"，且账本同步留条 | AP-01（存在性当证据）/ 审计器被"哄"过去 |
| P2 | **不许为消账而误标**：复核后发现并未解决的，**退回未解决**并进波 3，不得为了"账本好看"翻状态 | AP-04（账本与状态脱钩）反向版 |
| P3 | **补账 ≠ 重跑**。补账只把**已有记录**转录成模板结构，无记录者标 `BLOCKED`（语义 = 证据未记录）；**要变成 PASS 只能靠真跑** | 把"补文档"当成"还了账" |

## 3. 关键设计决策：为什么"先补账、再堵漏、最后补真证据"

上一轮已验证的教训排序：

1. **07~10 的四个 PR 全部 CI 全绿着合并了**，而它们收口全不合格 ⇒ **CI 拦不住收口问题**，因为审计器不在 CI 里。
2. 若**先**把审计器接进 CI（此时 `--all` 有 4 个 FAIL），CI 会立刻常红 → 按项目自己的话，**"永远红的门禁会训练所有人忽略 CI，比没有检查更糟"**（remediation.md R-01 ③ 的原话）。于是只能加基线白名单，而**白名单一旦存在就会长期存在**。
3. 所以正确顺序是：**先把 `--all` 补到 0 FAIL，再接 CI 并直接设为 required —— 不需要白名单，门禁从第一天就是真严格的。**

这个顺序是本计划的核心，不是排期偏好。
