# E2E-09 注册流程

## 1. 阶段目标

改造并跑通注册流程：**删除已失效的验证码步骤**、新增强制性的**密保问题设定弹框**（D-01），并验证注册全流程与后续找回密码的联动。

## 2. 范围与边界

### 做

**改造部分**（D-01 细化决议，见 [decisions.md](../../decisions.md)）：

| 项 | 现状（已核实 `login/index.vue`） | 改造后 |
|----|-------------------------------|--------|
| 验证码字段 | `registerInfo.verificationCode` + `code-field`（`获取验证码` 按钮）+ `code-hint`（"开发模式下验证码会打印在服务端终端"） | **全部删除**（无投递渠道，已用不到） |
| 密保设定 | ❌ 无 | **新增弹框**：1~2 个问题 + 答案，**不可跳过**（关闭即中止注册），弹框内提示「此密保用于找回密码」 |
| UI 空间约束 | `.login-card` 为固定布局且 `overflow: hidden`（`:218`），注册表单已有 3 字段 | **必须用弹框**，不塞进卡片（塞进去会被裁切） |
| `verificationCodeCountDown` | 注册流程使用 | 评估是否仅保留给其他流程（若无其他使用方则一并清理） |
| BFF `verification-code` | `register` 校验 `verifyVerificationCode` | 移除注册路径的验证码校验；是否整端点下线需确认无其他调用方 |

**验证部分**：

| 功能 | 涉及 |
|------|------|
| 注册 tab 切换 | `web/app/pages/login/index.vue` |
| 用户名/密码校验 | `registerInfo` + 前端校验（`:138`） |
| 密保弹框交互 | 新建组件（建议 `app/components/`） |
| 注册成功行为 | 返回 LoginData（自动登录？） |
| 重复用户名 | `users.username UNIQUE` |
| 与找回密码联动 | 新增账号可走通 E2E-07 |

涉及文件：

| 层 | 文件 |
|----|------|
| 页面 | `web/app/pages/login/index.vue`（注册 tab） |
| 状态 | `web/app/stores/user.ts`（`register()` / `sendVerificationCode()`） |
| BFF | `bff/internal/handler/auth_handler.go`（`register` / `verification-code`） |
| 用户服务 | `user-svc` `Register`（bcrypt） |

### 不做（边界）

- 第三方登录（OAuth 已删，ADR-21）
- 邮箱/手机号采集（D-01 已排除，`phone`/`email` 字段在 E2E-06 删除）
- 注册后的新手引导
- 登录后补设密保的提醒流程（属 E2E-06 连带后果选项 B，若采纳则另立）

## 6. 已知风险

| 风险 | 应对 |
|------|------|
| 删验证码会牵动 `stores/user.ts` 的 `sendVerificationCode`、BFF 端点、架构测试多处 | 先 grep 出完整影响面清单，再决定是"仅删注册路径调用"还是"端点彻底下线" |
| 弹框不可跳过会抬高注册门槛，若用户中途关闭则注册失败 | 明确交互：关闭按钮 = 中止注册（**不产生半成品账号**）；测试点 8 专门断言 |
| 密保问题的答案区分度（大小写/空格）未定 | 需定归一化规则（建议 trim + 忽略大小写），并写入测试点 |
| 存量未设密保用户无法找回（见 E2E-06 连带后果） | E2E-06 开工前明确选项；本阶段只保证**新注册**用户链路完整 |
