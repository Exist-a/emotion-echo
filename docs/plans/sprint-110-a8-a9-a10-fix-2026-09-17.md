## 二、根因诊断

### A8 真根因 — Vue 3 路由切换 + onUnmounted abort race

**链路**：
1. `new.vue:122` → `conversationSender.createNewConversation(value)`
2. `useConversationSender.ts:195` `await navigateTo({ name: 'chat-conversation-detail' })`
3. Vue 3 nextTick 后同步触发 `new.vue` 的 `onUnmounted` → 调 `cancelAIStream()`
4. `useAIStreamHandler.ts:59` module-scope `streamAbortController` 此时为 null → cancel no-op
5. `useConversationSender.ts:200` `await nextTick()` → 触发 `new.vue` 卸载完成
6. `[id].vue` mount 时调 `useConversationSender()` 新实例 + 注册新 `onUnmounted`
7. `useConversationSender.ts:204` `await sendToExistingConversation` → `await sendAIStream`
8. `useAIStreamHandler.ts:81-83` `if (isStreaming.value) return '正在对话中'` —— **若上一次流因任何原因 finally 块未跑完，isStreaming 卡在 true → 当前 sendAIStream 直接被 guard 拒**
9. 即使 guard 通过，`streamCancelled.value` 未在 finally 中清零 → 下一次 createFlow 仍可能命中 cancelled 残留

**更深层根因**：`createNewConversation` 让"发送"的责任跨了组件实例边界。`new.vue` 创建会话 A，调用 sender A 的 `createNewConversation`，navigate 后 A 实例销毁；sendToExistingConversation 闭包还在跑——跨实例 SSE 状态在 race 下丢。

### A9 真根因 — sidebar-header flex 容器宽度溢出

`emotion-echo-web/app/pages/chat/conversation/index.vue:263-269`：
```scss
.sidebar-header {
  display: flex;
  align-items: center;
  gap: 8px;
  ...
}
```
fold-btn (30px) + h3.title (flex:1) + new-btn (30px) 在 sidebar 宽 250px 减 padding 24px = 226px 可用空间下，标题被挤窄 → fold-btn 与标题间距不规则。

### A10 真根因 — voice-btn 样式优先级

`emotion-echo-web/app/pages/chat/conversation/[id].vue:636-643` `.voice-btn` 期望 `var(--ee-primary-soft)` 浅绿背景，但实测深绿。问题：
- 全局 `.icon-btn` 选择器优先级与 `.voice-btn` 相当（specificity 0,1,0）
- `var(--ee-primary-soft)` 未定义时回退到 default（浏览器默认）→ 实际看是 `var(--ee-primary)` 被某处继承
- 父级 `.composer-actions` flex gap 8px + padding 可能挤压按钮尺寸
