## A. dev 模式用户路径阻断（影响"产品能否使用"）

### A1. TTS 语音回复不可用 🔴（产品功能缺失，非路径问题）

- **现状实测**（2026-09-04）：
  ```
  $ curl -X POST http://localhost:19080/api/v1/tts/synthesize \
      -H "Content-Type: application/json" -d '{"text":"hi"}'
  {"error":"Get \"http://emotion-echo-xtts:8003/health\": context deadline exceeded"}
  ```
- **根因链**：XTTS 容器已在 Stage 39 §五被删除（依据是 ai-svc 容器无 `XTTS_BASE_URL` env，
  `aiclient/xtts.go` 空即返 nil）。**删除合理**——但前端 TTS 按钮没同步下线，
  实际上仍是"用户点 TTS 收不到任何东西"。
- **未做原因**：构建 XTTS 镜像受 Stage 36 记录的"pypi CDN 0 字节响应 + Docker Desktop
  内存限制 30+ 分钟"卡死。生产网络跑可能一次成。
- **修复路径（任选一）**：
  1. 生产网络重建 XTTS 镜像：半天到一天
  2. 前端降级到 Web Speech API：几小时（音色能力下降）
  3. 干脆前端下线 TTS 按钮
- **需要决策**：方案 1 vs 2 vs 3

### A2. 文件上传后端未实现 🟡（Stage 30 T4.58 占位）

- **现状实测**（2026-09-04）：
  ```
  $ curl -X POST http://localhost:19080/api/v1/uploads/image -H "X-User-Id: 1"
  {"code":1,"message":"uploads not implemented (Stage 31)"}
  HTTP 502
  ```
- **根因**：`emotion-echo-web-bff/internal/handler/upload_handler.go` 头部注释明写
  "Stage 31（引入对象存储）"。**注意**：是 502 而非 404，Stage 38 §三阻断 2 把这条
  记为"路由 404"是误诊，本轮已纠正。
- **前端代码现状**：`Emotion-Echo-Web/app/composables/useFileUpload.ts:42-46`
  调的是**单数** `/upload/image`/`/upload/video`/`/upload/file`，而 BFF 注册的是
  **复数** `/uploads/:kind`（`upload_handler.go:27`）。即使后端实现，路径仍然对不上。
- **修复路径**：先做对象存储选型（MinIO 自建 / 云 OSS），再补后端，**同步修前端路径**。
  两端都得改，是同一笔工作量。
- **需要决策**：MinIO vs 云 OSS（自建无云依赖但要管存储；云省事但引入凭证管理）

### A3. 前端 Nuxt dev server 需要用户手工起 🟡

- **现状实测**（2026-09-04）：`http://localhost:3000/` 301（指向 /login），
  `/login` 200 但内容是 Nuxt 客户端 SPA 壳，**首屏完全靠 JS 在浏览器里渲染**。
  也就是说前端的 HTML 是空的，所有逻辑靠 hydration。curl 看不到任何实质内容。
- **唯一阻断**：用户从仓库 clone 后必须手工 `cd Emotion-Echo-Web && pnpm install && pnpm dev`。
  README 写了这步，但新人未必看到。
- **修复路径**：
  1. 在 QUICKSTART.md 顶部加"5 秒必读"小框，明确"前端是独立进程，要单独起"
  2. 或者起一个 `make dev` / `pnpm dev:all` 同时起前后端
- **预估**：1 小时

## B. APISIX / Nacos / 配置中心遗留（架构层面）

### B1. 容器化前端对 BFF 端口的依赖仍存在 🟡（dev 例外，非修复）

- **现状实测**（2026-09-04）：
  ```
  emotion-echo-web-bff  0.0.0.0:8894->8894/tcp
  ```
- **根因**：`deploy/docker-compose.apps.yml:545` 注释
  ```
  # Stage 33 PR-20: BFF 端口保留（dev 调试 / Postman 直连；prod 应仅暴露 APISIX）
  ```
  这是**有意保留的 dev 例外**。本轮我曾误判它"与决策 12 不符"（cf. 决策 18 实例 #1），
  实测后发现是注释已经写明"prod 应仅暴露 APISIX"。
- **风险**：dev 环境下绕过 APISIX 直连 BFF 是可行的。BFF 自身不验签（决策 12
  "BFF 内部鉴权：不做"），只信任 `X-User-Id` header——直连的人塞 `X-User-Id: 1` 就能
  假冒任何用户。dev 监听本机问题不大，prod 部署必须确认 compose 不暴露 8894。
- **修复路径**：
  1. dev 保留现状，prod compose 用独立 profile / 显式不开 ports
  2. 或者在 web-bff 服务上加注释"prod 必须用 ports: []"
- **建议**：写明"prod profile" compose 覆盖文件。

### B2. Nacos Go SDK 升级阻塞 🟡

- **根因**：Nacos Go SDK v2.3.5 与 Server v2.4.3 long poll 路径不匹配——
  SDK v2.3.x 走老的 `/listener`，Server v2.4.3 走 `/config/listener`，导致配置
  热更新推送无法触发回调（`ListenConfig` 挂上后 web-bff 收不到 callback）。
- **修复路径**：等 Nacos Go SDK 官方发 v2.4 stable tag；或临时降级 Nacos Server 到
  v2.3.x（Stage 39 §四.4 记录过 v2.3.2 Register 返 400 失败）。
- **当前不阻塞**：dev 用作开关即可，启动时 GetConfig 仍正常；热更新是 prod 才需要。

### B3. APISIX 配置中心 seed 与运行期 host 列表 🟢

- **现状**：`charts/emotion-echo/charts/apisix/values.yaml` 里 `nacos.host` 默认
  `emotion-echo-nacos:8848`（dev 单节点）。prod 需要多节点。
- **影响**：仅 prod 范围。

### B4. AI 服务容器（fer / sensevoice / xtts）被删意味着多模态功能不可用 🟡

- **现状**：Stage 39 §五把这三个本地 AI 模型容器都删了（依据是 ai-svc 容器无对应
  BASE_URL env，ai-svc 端空即返 nil）。这意味着**人脸情绪识别、语音转录**这两类
  多模态输入是空跑——前端点对应按钮，要么直接报错，要么上传了但没结果。
- **影响范围**：比 A1 范围更广。A1 只是 TTS 输出端，B4 是**输入端**两个功能都废。
- **修复路径**（与 A1 类似，需决策）：
  1. 重建 FER + SenseVoice 镜像（与 XTTS 同样的构建环境问题）
  2. 把多模态降级为"纯文本情绪"——前端去掉对应入口

  等多种可能，未结案。
- **本轮新增证据**：smoke §4 `/reports/daily` 实际查 `msg_summary_v` 视图，该视图建
  在 `emotion_echo_chat.messages` 等表上。**全新环境缺此视图**时返 500。**如果 dev
  库历史上长期缺该视图**，dashboard 空的现象与"视图不存在 → SQL 报 column 不存在 →
  兜底为空"完全自洽。
- **待办**：回查 Stage 36 时的 dev 库是否真的缺 `msg_summary_v`（即本轮已落地的
  `analytics/001`）。这若是根因，则 Stage 36 报告的 G4 类问题本质都是 migrations

### C8. **新增** BFF 路由清单无契约测试 🆕

- **现状**：`emotion-echo-web-bff/main.go` `registerRoutes` 函数用 `r.POST(...)` 散
  装注册，**没有任何文件**断言"这些路径的集合是 X"。前端/契约测试只能事后端
  `curl` 验证。Stage 38 §三阻断 2/3 误诊就是这类问题的副作用——没有源生清单，
  curl 404 之后排查"是路由缺失还是路径写错"要读 handler.go。
- **修复路径**：写一个 `_test.go` 用 Go 反射（或直接拉一个全局 list）断言
  `registerRoutes` 注入的路径集合是 `{[/health /metrics /api/v1/auth/:action ...]}`。
- **预估**：1-2 小时（含契约 4/5/6 同步加 seed 端的覆盖）。
