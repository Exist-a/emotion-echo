## §一 决策 1 · 隐私定位

### 1.1 选项

| 选项 | 描述 | 影响 |
|------|------|------|
| **(a) 推理本地 + 消息照常上传**（v0.2 倾向）| 端侧推理 = 隐私卖点；用户消息仍走 BFF→chat-svc 入库 + 上报（保留会话历史 / 报表 / 测评）| 管道零改动；离线工程量小；报表零感知 |
| **(b) 真·数据不离设备** | 用户消息不入库，不上报，不上报情绪事件；端侧推理 + 本地 Dexie 缓存 | 报表 / 画像 / 历史回显需整套本地双轨；换设备失忆；测评离线不可用 |

### 1.2 v0.2 §十二 倾向 = **(a)**

**推荐理由**：
1. **管道零改动**：BFF / chat-svc / analytics-svc 全链路不变；端云分流只动 `useAIStreamHandler.sendAIStream` 单点（v0.2 §3.2 插入口证据）
2. **隐私卖点成立**：端侧推理完成的事**永不上云**（强约束 = prompt + 模型权重本地）；与 §1.3 原则 2「来源显性可见」配合 → "本地完成"角标
3. **离线工程量小**：v0.3 §E OC-02~OC-04 离线契约 = 仅 outbox 补发；不需要本地双轨数据库
4. **报表零感知**：E2E-15 留账 §9 #2（trigger HTTP 实际是 BFF 未暴露端点）不引入新分支

**风险**：
- (a) 不代表"消息不上传"；仅"推理本地"——必须配合 §三 来源告知（角标）
- (b) 工作量大 + 报表断链 + 用户口径变化（"为什么我没历史？"）

## §三 决策 3 · 来源告知方式

### 3.1 选项

| 选项 | 描述 | 影响 |
|------|------|------|
| **(a) 「本地完成」角标**（v0.2 倾向）| AI 回复气泡右上角 / 底部加 "本地完成" / "云端回复" 角标；用户一眼能识别回复来源 | UI 改动量小；隐私宣传口径强；与 §一 (a) 配合 = 卖点显性可见 |
| **(b) 纯无感降级** | 端云回复外观一致；用户不知道哪条来自哪边 | 隐私卖点减弱；用户对"永不离设备"产生错误预期 |

### 3.2 v0.2 §十二 倾向 = **(a) 角标**

**推荐理由**：
1. **大厂先例**：Apple Intelligence（端侧 vs PCC vs 第三方）+ Google Gemini Nano（端侧任务有标识）—— 路线被产品化验证
2. **诚实原则**：v0.2 §1.3 原则 2 "过程平滑无感、来源显性可见" —— 心理学场景信任建立核心
3. **降级透明**：v0.2 §5.4 切换本身平滑不中断 + 显性角标 = 既不打扰又有信号
4. **UI 改动可控**：单组件复用，仅多一层角标 wrapper

**风险**：
- 角标过强 → 用户对"为什么不全本地"产生疑问（解释成本）
- 角标过弱 → 隐私卖点看不出来（"勾选"模式）

**UI 实现建议**：
- 端侧回复 → 角标 "🛡️ 本地完成"
- 云端回复 → 无角标（默认态）或 "☁️ 云端回复"
- 高危×离线 → 强制弹援助热线（v0.2 §5.1 "高危×离线"兜底），不算来源告知

### 3.3 决策 3 落定后派生契约

| 派生 | 影响 |
|------|------|
| **OC-08 端云共用同一 prompt 组装层** | 角标实现需在 chat-svc 入库前加 `reply_source` 字段（`local`/`cloud`/`hotline`），与 v0.2 §3.2 prompt 组装层对接 |
| **端云比例埋点（OC-10）** | 决策 3 = (a) ⇒ 埋点必有 source 字段；E2E-21 收口后接入 Grafana |

## §四 决策 4 · 离线范围

### 4.1 选项

| 选项 | 描述 | 工作量 |
|------|------|--------|
| **L0**（v0.2 §5.5 必须）| 已有会话内正常对话 + 断网消息排队重连补发 | 1 周 |
| **L0 + L1**（v0.2 倾向）| L0 + 浏览已同步过的历史 | 2~3 周 |
| **全 L0-L2** | L0+L1 + 离线新建会话 + 重连 reconcile | 6~8 周（含双轨架构）|

### 4.2 v0.2 §十二 倾向 = **L0 必须 + L1 应做，L2 二期**

**推荐** = **L0 + L1**（与 v0.2 倾向一致；不做 L2）。

**L0 验收契约**（v0.3 §E OC-01~OC-04）：
- OC-01：已有会话内正常对话（断网 → 端侧回复 → 重连 → 全部入库）
- OC-02：outbox 消息按 sendTime 保序（vitest flush 函数单测）
- OC-03：AI 回复补传契约 clientMsgId 幂等（vitest + E2E 双设备）—— **决策 1 = (a) 强依赖**
- OC-04：JWT 离线宽限期（在线提前 N 分钟刷新，vitest + E2E 离线鉴权）

**L1 验收契约**（v0.3 §E OC-05）：
- OC-05：离线 L1 浏览已同步过的历史（E2E Playwright 断网 → 历史页可访问）

**L2 风险**（v0.2 §5.5 标注为「二期」）：
- 临时会话 ID 机制 + 重连 reconcile + 本地/服务端会话双轨，工作量大
- 决策 1 = (b) 时才**必须**；决策 1 = (a) 可不做

### 4.3 决策 4 落定后派生契约

| 派生 | 影响 |
|------|------|
| **OC-07 不可用场景显式降级** | L0+L1 范围下报表 / 测评 / TTS / 数字人 / 新设备登录 = 显式降级（"联网后可用"提示）|
| **E2E-29 收口强依赖** | JWT 离线宽限（OC-04）依赖 E2E-29 横切：异常与安全 |
| **E2E-30 收口强依赖** | AI 回复补传契约（OC-03）必须通过 §2.4 六项契约 |

## §五 决策 5 · 记忆/摘要存储

### 5.1 选项

| 选项 | 描述 |
|------|------|
| **(a) 随决策 1 联动**（v0.2 倾向）| 决策 1 = (a) ⇒ 摘要服务端生成下发；决策 1 = (b) ⇒ 摘要本地 |
| **(b) 强制本地** | 不论决策 1，必须本地摘要；换设备失忆 |

### 5.2 v0.2 §十二 倾向 = **(a) 随决策 1 联动**

**推荐** = **(a) + 决策 1 = (a) ⇒ 摘要服务端生成 + 下发**

**理由**：
1. **换设备一致**：服务端摘要保证用户切换设备仍能看到历史摘要
2. **离线可用**：客户端缓存最近一份（OC-08 端云共用组装层）
3. **端侧算力节省**：摘要可搭云端回复的便车生成（v0.2 §6.2 "L2 摘要可搭云端那轮顺带"）
4. **隐私等价**：决策 1 = (a) ⇒ 消息本来就在服务端，摘要不引入新隐私面

**实施**（v0.2 §6.2）：
- L0 当前轮 user 消息：永远保留
- L1 滑动窗口最近 3-4 轮原文：端侧窗口开小（小模型长上下文注意力衰减快）
- L2 滚动摘要（每 K 轮压一次）：服务端生成 + 下发
- L3 结构化事实卡片：规则/正则抽取，**不经过模型**（零幻觉）

### 5.3 决策 5 落定后派生契约

| 派生 | 影响 |
|------|------|
| **OC-08 端云共用同一组装层** | 摘要从第一天就由同一组装层喂两边（v0.2 §6.2 强约束）|
| **决策 1 = (b) 联动** | 若决策 1 = (b)，决策 5 须同时 = 本地（不接受换设备失忆）|
