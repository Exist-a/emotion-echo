# ADR: 验收断言必须断言**取值**，不得只断言**形状**

## 上下文

2026-09-21 复核 E2E-14 时，实测发现 **PHQ-9 / GAD-7 的症状算分是错的**（账本 `E2E-F-97`），
而这个缺陷**在两次已收口的阶段里都被标为 PASS**：

| 现象 | 实测 | 应有 |
|------|------|------|
| 全选"完全没有"（无症状） | `totalScore=9 / riskLevel=mild（轻度）` | `0 / none` |
| 选任一题"几乎每天" | `HTTP 400 answer q1 must be 0-3, got 4`（4 是 option.id） | `200 / 27 / extreme` |

根因：前端提交 `option.id`，后端按 `score` 计分；种子数据里 PHQ-9/GAD-7 是
`id 1..4 / score 0..3`（**id = score + 1**），BIG5 恰好 `id == score` 才一直没暴露。

**缺陷为什么能连续逃过两次验收** —— 断言只写形状，不写取值：

| 阶段 | 断言原文 | 为什么放过 |
|------|---------|-----------|
| E2E-13 #6-9 | 「断言弹窗含 totalScore **数字** + riskLevel 文本」；「riskLevel 匹配 `/正常\|轻度\|中度\|重度\|极重度/`」 | `9` 是数字、`轻度` 匹配正则 ⇒ **形状对，值错** |
| E2E-13 #6-9 | 每题只点**第一个选项**（id=1） | 绕开了唯一会触发 400 的档位（id=4） |
| E2E-14 #4/#12 | 只测 BIG5 | BIG5 恰好 `id == score` ⇒ 测不出该 bug |
| E2E-14 #11 | 断言"提交响应 == 列表项 == 详情"三处一致 | **一致 ≠ 正确**（三处可以一起错） |
| E2E-13 #4 | 断言文案写「标题、**描述**、题数」，实际只验前两个 | 描述恒空被放过（`E2E-F-91`） |

即：**断言文案点名的东西必须逐个真正断言**，且**必须给出期望的具体值**。

## 决策

### 决策 1：验收断言必须包含**具体期望值**，不得只断言类型/非空/正则形状

- ❌ `expect(typeof data.totalScore).toBe('number')` / `toBeDefined()` / `toContainText(/正常|轻度|…/)`
- ✅ `expect(data.totalScore).toBe(0)` + `expect(data.riskLevel).toBe('none')`

形状断言只在**无法预知取值**时使用（如真实 LLM 的自由文本），且必须同时给出
可判定的**结构约束**（长度上下界、必须含/不含某类词），而不是"非空即可"。

### 决策 2：边界两端都要测

数值型契约必须测**两端**（最小值与最大值），因为越界/偏移类缺陷只在某一端暴露 ——
本题正是"最小值端被静默读错 + 最大值端直接报错"。

### 决策 3：一致性不等于正确性

「多处一致」是**弱证据**，不能替代期望值断言。三处可以一起错（本题：提交响应、
列表项、详情三处一致，但一起错）。若只能验一致性，必须额外给出**独立算出的期望值**。

### 决策 4：驱动路径必须覆盖真实用户路径

本题只在 UI 路径错（前端送 id），API 直传 score 是对的 ⇒ 只测 API 的用例**结构性**地
测不出它。涉及"某层转换"的契约，回归钉必须有一条**走真实 UI 驱动**的用例。

### 决策 5：`totalScore` 的语义必须显式（`scoreKind`）

人格量表的 `totalScore` 是五维度之和（全中立 = 90），**无严重度语义**，却与症状量表
同名字段返回。新增 `scoring.Result.Kind` / 响应字段 `scoreKind`
（`risk` / `dimension_sum` / `ratio`），由各 scorer **自述**，消费方按字段判断，
不必记 `riskLevel` 的魔法值。

## 后果

- **正面**：断言能真正发现取值错误；两端覆盖抓住越界类缺陷；`scoreKind` 让下游不必猜语义
- **正面**：与既有 `E2E-F-91`（弱断言）合并为一条可机械检查的规则，可写入后续阶段的 plan 模板
- **负面**：断言更啰嗦，需要先算出期望值（成本转移到写测试的一方，但这是应当的成本）
- **负面**：真实 LLM 输出无法给绝对期望值，该场景只能退化为"结构约束 + 人工/判官"，此时必须**显式声明该证据的强度上限**（见 `E2E-F-98`：判官证据在补负对照后不成立）
- **后续**：`docs/e2e-roadmap/stages/_TEMPLATE.md` 与 `_REPORT_TEMPLATE.md` 应在验收章节
  提示"期望值断言 + 边界两端 + UI 驱动路径"
