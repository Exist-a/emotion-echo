# ADR-2026-09 端侧化离线范围 = L0 + L1（L2 二期）

> **状态**：🟢 **accepted**（2026-09-28 用户拍板；Lane O 立 ADR）
>
> **取代关系**：无（本项目首个端侧化离线范围决策；v0.3 §B.1 决策 4 落地）
>
> **关联**：D-26 + D-26.1（强联动：决策 1=(a) 当前拍板 ⇒ L0+L1 应做；决策 1=(b) 未来切换 ⇒ 需 L2 双轨）
>
> **拍板记录**：用户 2026-09-28 在 Lane O 会话中通过 AskUserQuestion 工具拍板；拍板原文：「L0 + L1（L2 二期）」

## 一、决策

按 v0.2 §十二 决策 4 + v0.3 §B.1，端侧化离线范围选 **L0 + L1（L2 二期）**。

| 路径 | 描述 | 工作量 | 拍板结果 |
|------|------|--------|----------|
| L0（必须）| 已有会话内正常对话 + 断网消息排队重连补发 | 1 周 | — |
| **L0 + L1**（**当前**）| L0 + 浏览已同步过的历史 | 2~3 周 | **🟢 接受** |
| 全 L0-L2 | L0+L1 + 离线新建会话 + 重连 reconcile | 6~8 周（含双轨架构）| 决策 1=(b) 时未来排期（决策 1 拍板：b 等排期）|

## 二、L0+L1 验收契约（v0.3 §E OC-01~OC-07）

### 2.1 L0 必做契约

| 契约 ID | 验收点 | 类型 | 阻塞门 |
|---------|--------|------|--------|
| **OC-01** | 已有会话内正常对话（断网 → 端侧回复 → 重连 → 全部入库）| E2E Playwright | 决策 4 = L0+ |
| **OC-02** | outbox 消息按 sendTime 保序（vitest flush 函数单测）| vitest | 决策 1 = (a) |
| **OC-03** | AI 回复补传契约 clientMsgId 幂等（vitest + E2E 双设备）| vitest + E2E | 决策 1 = (a) 强依赖 |
| **OC-04** | JWT 离线宽限期（在线提前 N 分钟刷新）| vitest + E2E | E2E-29 收口 |

### 2.2 L1 应做契约

| 契约 ID | 验收点 | 类型 | 阻塞门 |
|---------|--------|------|--------|
| **OC-05** | 离线 L1 浏览已同步过的历史（E2E Playwright 断网 → 历史页可访问）| E2E Playwright | 决策 4 ≥ L1 |

### 2.3 不可用场景显式降级（OC-07）

| 场景 | L0+L1 范围下处理 |
|------|------------------|
| 报表 / 测评 | 显式降级（"联网后可用"提示）|
| TTS / 数字人 | 显式降级 |
| 新设备登录 | 显式降级（需在线）|

### 2.4 L2 二期（不实现）

| L2 能力 | 工作量 | 决策依赖 |
|---------|--------|----------|
| 离线新建会话 | 2 周 | — |
| 重连 reconcile | 2 周 | — |
| 本地/服务端会话双轨 | 4 周 | 决策 1=(b) 时才**必须**|

## 三、影响面

### 3.1 决策 4=L0+L1 直接影响

- **chat-svc** 实现 outbox 补发 + JWT 离线宽限支持
- **web 前端** Dexie 历史缓存接线（基建已有 v0.2 §3.1 评估）
- **BFF** `/api/v1/ai/stream` 端点支持断网重连
- **E2E-29 强依赖**（横切：异常与安全）

### 3.2 决策 4=L0+L1 派生约束

| 派生 | 影响 |
|------|------|
| **OC-08 端云共用同一 prompt 组装层** | L1 离线 LLM 推理 + 服务端同步后历史/上下文一致 |
| **OC-03 AI 回复补传契约** | L0 必做（OC-03）|
| **OC-07 不可用场景显式降级** | L0+L1 范围下报表/测评/TTS/数字人/新设备登录 = 显式降级 |
| **决策 1 联动**（D-26.1）| 决策 1=(a) ⇒ L0+L1 应做（OC-05 必做）；决策 1=(b) ⇒ 需 L2 双轨（工作量大增）|

### 3.3 全 L0-L2 备选代价（如选此项）

- 工作量 6~8 周（含双轨架构 v0.3 §C.3 阶段二 L2）
- 临时会话 ID 机制 + 重连 reconcile + 本地/服务端会话双轨
- 决策 1=(a) 时**不必要**（决策 1=(a) ⇒ 消息本来就在服务端，L2 双轨没意义）
- E2E-29 强依赖不变

### 3.4 L0-only 备选代价（如选此项）

- OC-05 离线 L1 历史浏览**不可用**（v0.3 §E 验收契约挂）
- "端侧化 + 离线可用"卖点减弱（用户场景：地铁/飞机 = 期望能看历史）
- 用户体验断层（能发消息不能看历史）

## 四、调研依据

### 4.1 v0.2 §5.5 离线能力分层与四问题

```
1. 断网消息堆积补发（outbox 模式）—— 地基已有一半（Dexie + clientMsgId + online 事件钩子）
2. 无网络功能可用：
   a. 端侧推理可用
   b. 会话与历史可用
   c. 登录态：离线无法刷新 JWT（OC-04）
3. 端侧 AI 回复补传：客户端携带完整离线回复 POST + 幂等 + 保序（OC-03）
4. 多端乱序/冲突：保序 + clientMsgId 幂等
```

### 4.2 v0.2 §十二倾向

> **L0 必须 + L1 应做，L2 二期**

### 4.3 同业先例

| 产品 | 离线范围 | 实现方式 |
|------|----------|----------|
| Signal | L0-L1（消息/历史）| IndexedDB + 端到端加密 |
| WhatsApp | L0 only（消息队列）| 多端 reconcile 复杂 |
| Apple Messages | L0-L1 + iCloud 同步 | — |
| Jan（OpenAI 兼容端侧 LLM）| L0（仅本地推理）| 无云端 |

### 4.4 风险评估矩阵

| 风险 | 路径 | 概率 | 应对 |
|------|------|------|------|
| JWT 过期致离线全失效 | L0+L1 | 中 | OC-04 离线宽限期（在线提前 N 分钟刷新）|
| L1 历史缓存不命中 | L0+L1 | 中 | OC-07 显式降级 |
| 多端乱序/冲突 | L0+L1 | 低 | 保序 + clientMsgId 幂等（v0.2 §5.5 #4）|
| 离线可用性卖点夸大 | L0+L1 | 中 | OC-07 显式降级（v0.2 §5.5 验收分层表）|
