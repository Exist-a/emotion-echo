# ADR-2026-10: 用户自定义角色（Agent）身份层 —— 与 ADR-2026-09「相处说明书」的关系

## Status

✅ **Accepted**（2026-10-17 · CL-06 推进；本 ADR 为 `adr-2026-09-personality-prompt-semantics.md` **决策 1** 的**边界修订**，不废除原 ADR）

- 上游组装层：`docs/legacy-plans/landed/prompt-pipeline-redesign.md`（CL-04 已落地，本 ADR 新增**一个段**）

## Context

**为什么要修订**：原 ADR 的语境是**"AI 的人格从哪来"** —— 当时唯一的个性化来源是**测评五维自动推断**，其风险是"AI 演性格 ⇒ 崩成话痨/客服/说教，而用户要的是**自己被理解**"。因此选择"给 AI 一份**关于这个人的相处说明书**"，并写死"基底人设一字不改"。

**新需求（用户 2026-10-13 / 2026-10-17 拍板）**：用户要**能拥有"自己的"陪伴者** —— 给它起名、给背景、选语气、选音色，并且**可建多个**（每户 ≤5）、**在会话内随时切换**（`CL-D-23`）。这与"基底人设一字不改 + 不做 AI 性格"**直接冲突**（不是补充），因此不能只写进实施计划，必须**修订 ADR**（否则违反 AP-08「架构改动无 ADR」）。

**与旧决策的真实关系**（不是推翻）：

- 原决策反对的是**"服务端替用户决定 AI 的性格"**（演出来的性格，且用户不可控）；
- 本决策引入的是**"用户显式设定的身份"**（用户自己写的，且随时可改可删）；
- 两者的**共同底线**相同：**不冒充真人、不宣称资质、不点破来源**。

## Decision

**在 CL-04 的 Prompt 组装层中新增一个"用户角色段"，作为与"测评相处说明书段""情绪段"并列的独立段；角色身份由用户显式设定，优先级高于测评推断，但整体运行在不可覆盖的"安全信封"内。**

1. **基底人设仍保留且不改**：`baseSystemPrompt`（`prompt_templates.go:37`）一字不改；用户角色是**叠加层**，不是替换层。
2. **段序（canonical，钉死）**：`base → agent（用户角色）→ personality（测评相处说明书）→ emotion（情绪）→ guard（护栏）`。
   **`guard` 段必须永远排在最后** —— 这正是 `prompt_assembly.go:63-66` 注释预留的要求（"用户可控内容之后必须有护栏段兜底"）。
3. **优先级**：`boundaries`（用户负向约束）**恒最高** → 用户显式设定（name/persona/tone）**覆盖测评段同类措辞** → 测评仍提供"联系方式"（除非与前面冲突）。
4. **安全信封不可覆盖**（用户动不了、关不掉）：① 受限槽位（不允许写裸 system prompt）；② 每字段长度上限；③ 保存时规则式黑名单（越狱句式 / 宣称资质 / 冒充真人）；④ `guard` 段**后置**；⑤ **危机处理独立于人设**（人设关不掉它；实施见 `CL-08e`，本 ADR 只保证不破坏该链路）。
5. **零回归是硬约束**：**无角色设定**（或角色被删光）⇒ prompt 与行为**逐字等于现状**。增强不是依赖。
6. **适用范围**：本决策**只覆盖"用户自定义角色"这一条链路**；**不改**测评画像（`personality_directive.go`）与情绪回显（CL-07）的既有语义。
7. **可追溯**：每条 AI 消息记录 `agent_id`（写入时快照），用于历史标注"这条是谁回的"。

## 被否的备选

| 备选 | 否决理由 |
|---|---|
| 只写实施计划、不修 ADR | 违反 AP-08「架构改动无 ADR」；且后来人会拿原 ADR 决策 1 断言"本功能不该存在" |
| 用"共享说明书"措辞绕开（把角色说成"相处偏好"） | 掩盖真实语义：用户给的是**身份与名字**，不是"怎么跟他说话"；措辞滑移会让验收标准失焦 |
| 允许用户直接写裸 system prompt | 越狱面直接敞开（原 ADR 的护栏意图全废）；改为**受限槽位 + 结构化字段** |
| 删掉基底人设、完全由用户角色替代 | 未设角色的用户（大多数）体验会退化；且失去统一的安全基调 |
| 让角色可覆盖危机处理 | 违"安全信封不可覆盖"原则（危机通道单列 `CL-08e`，与角色解耦） |

## Consequences

**正面**：

- 用户从"只能接受服务端推断的性格"变成**能拥有并随时切换自己的角色**（产品缺口补齐，也是演示/面试最直观的能力）。
- 与既有组装层**正交**：只新增一个段 + 一个护栏段，不重构 CL-04 的成果；零回归有 golden 字面量钉（阶段档 T-8）。
- 安全边界**显式可测**：段序（T-9）、优先级（T-10）、黑名单（T-11）都是机器可判的断言。

**负面 / 留账**：

- **prompt 变长**：角色段最多 500 字 + 护栏段，按 token 预算机制（CL-04 §G3）与 `agent` 段长度上限共同兜底。
- **与测评段存在真实竞争**：用"边界最高 + 用户显式覆盖同类"消解，但**未做真人评测**（与原 ADR 的同类限制一致，如实登记）。
- **音色只有云端（CosyVoice2 8 音色）支持**：XTTS 兜底窗口内音色会回落（`CL-D-25`：主链路已是云端）。
- **历史标注依赖快照**：角色被删后消息仍显示当时名字（有意为之，见阶段档 T-4）。
