Round C e2e 实证：chat-events 业务 topic 6 partition 验证
================================================================

执行环境：dev compose (deploy/docker-compose.infra.yml)
执行日期：2026-09-15
执行命令：
  docker compose -f deploy/docker-compose.infra.yml up -d kafka kafka-init
  # 等 kafka healthy 后自动触发 kafka-init (depends_on: service_healthy)
  docker exec emotion-echo-kafka bash -c "/opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --describe --topic chat-events"

清理旧 topic 步骤（dev 库历史残留 chat-events partition=1）：
  docker exec emotion-echo-kafka bash -c "/opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --delete --topic chat-events"
  # 删除后 kafka-init 重跑（IF NOT EXISTS 命中会跳过 — 删后才会真建 6 partition）

=== 业务影响 ===

旧 1 partition 限制：ai-svc + analytics-svc 2 consumer 共享 group，1 个 active 1 个 idle。
新 6 partition：2 consumer 各自 1 partition（均衡）；6 个 ai-svc 副本可全并行（chat-svc producer
按 conversation_id 哈希分区 → 同会话消息保证顺序性，跨会话可并行）。

上 prod 路径：env 改 KAFKA_TOPIC_REPLICATION_FACTOR=3 即可（init-topics.sh 已支持 override）。
