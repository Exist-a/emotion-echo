§8 六项 FAIL 的逐项归因（不写未经核实的"非本轨所致"）
======================================================================
判据（`scripts/smoke_data_layer.py:436-517`）：取**镜像** `docker image inspect {{.Created}}`，
与该服务 src_paths 的**最新 commit 时间**比较，`image_created >= svc_src_commit` 才算新鲜。
src_paths 对**每个**服务都包含 `emotion-echo-shared`（`smoke_data_layer.py:442-449`）。
该判据**仍为致命**是 2026-10-12 的**有意裁定**（账本 E2E-F-215 ✅ 已解决，原文：
"判据仍为致命：服务源码（含注释）改动仍会 STALE —— 源码变了就该重建"）。
⇒ 因此 §8 FAIL 的语义是「这些镜像比它们的源码旧，应当重建」，**不是**数据契约失败；
   §2.4 真正的契约项（§1/§2/§3/§4 数据面/§7）本轮全绿。

① 4 项落在"本轨只改了 shared、未改该服务自身源码"的服务：
   user-svc / assessment-svc / llm-service / web-bff
   —— 它们的 src_paths 含 `emotion-echo-shared`，而本轨改了 shared
   （`pkg/grpcinterceptor/tracing.go` + `tracing_go2sky.go` 新增 `EncodeSW8`）⇒ 判据据此判 STALE。
   （`git diff origin/main...HEAD --name-only` 可证这四个目录**确无**本轨改动。）
   本轨**未**重建这四个镜像（不属本阶段产物面）⇒ 保持 STALE，如实登记，不当作已解决。

② 2 项落在"本轨改了、且本轨**刚刚重建过**"的服务：ai-svc / analytics-svc
   —— 重建后**镜像 ID 已变**，但 `Created` **未前进**（Docker 沿用了缓存层的 config 时间）：

     $ docker image inspect emotion-echo/ai-svc:cl03        --format '{{.Created}} {{.Id}}'
     2026-10-16T05:13:02.3272778Z sha256:37289f56540c...   ← Created 与 smoke 记录的完全一致
     $ docker image inspect emotion-echo/analytics-svc:cl03 --format '{{.Created}} {{.Id}}'
     2026-10-16T05:14:30.046350675Z sha256:0d57c0f25c23...

     2026-10-16T06:10:56.397189857Z sha256:6aa71301dea0...  ← 该服务 Go 层变了，Created 前进 ⇒ 判 OK

   ⇒ 事实层面：**重建过的镜像也可能被判 STALE**（`Created` 未随内容前进）。
     本阶段**不改判据**（判据属 E2E-30 面、已裁定为致命），只如实登记该观察。
